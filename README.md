# Catime 番茄钟统计插件（pomodoro_stats）

在 Catime 窗口实时显示**今日 / 本周 / 累计**完成的番茄数，数据持久化，Catime 重启不丢失。

```
T3 W12  21:49       T = 今日   W = 本周(周一起算)   末尾是当前倒计时/时间
```

默认只显示**今日 + 本周**（本月与累计仍在后台记录）。想显示更多，改脚本顶部开关：

```powershell
$ShowWeek  = $true    # 本周
$ShowMonth = $false   # 本月
$ShowTotal = $false   # 累计
```

设成 `$true` 就会显示，例如全开时是 `T3 W12 M40 A57  21:49`。关掉的项**依然照常统计**，只是不显示。

## 计数口径（"1 个番茄"怎么算）

脚本顶部的 `$CountUnit` 提供两种口径，改一行即可切换：

| 值 | 含义 | 例：`25m 5m 25m 10m` 这样的一轮跑完 |
|---|---|---|
| `work`（默认） | 每完成一个**工作阶段**计 1 个 | 计 **2 个**（两个工作段） |
| `cycle` | 走完**一整轮**阶段序列（含休息）才计 1 个 | 计 **1 个** |

- **正统番茄工作法**里"番茄"指**一个工作时段**（经典 25 分钟），休息不算；
  "今天完成 8 个番茄"说的就是 8 个工作段 → 对应 `work` 口径。
- Catime 内部的 `complete_pomodoro_cycles` 数的是**整轮循环**（含休息），
  名字就叫 cycle / 循环，和"番茄"不是同一个概念 → 对应 `cycle` 口径。
- 两种口径都已实现并各自验证通过，按你的习惯选即可。

## 显示模式（`$TimerDisplayMode`）

| 值 | 效果 |
|---|---|
| `'timer'`（当前默认） | 推断"正在计时"时只显示计时，其余时间显示统计 |
| `'both'` | 始终显示 `统计 + 计时`：番茄钟每一段、普通倒计时都能看到计时 |

`'timer'` 想实现的是"番茄钟期间只显示计时、结束后自动回到统计"，但受一个**硬限制**：

> Catime 不提供"计时开始"的任何信号——开始计时既不写配置文件、也不新建窗口、也没有 IPC
> （源码已确认：计时开始路径不写任何配置项）。插件只能靠"上一次阶段完成 + 阶段时长"去**推断**。

因此 `'timer'` 模式的实际表现：

- ✅ 每轮番茄钟**第 1 段结束后**开始切换（后续各段都只显示计时），整轮结束回到统计；
- ⚠️ **第 1 段无法切换**（插件感知不到它开始了），该段仍显示"统计 + 计时"；
- ⚠️ 你**手动中断**计时后，统计要等该段预期结束时刻才会回来（最长等一段的时长）；
- ✅ 推断依据是真实检出的阶段完成事件，因此不会无故隐藏统计。

## 窗口大小与位置

Catime 对"插件模式"使用一个**独立的缩放档位** `PLUGIN_SCALE`（`config.ini [Display]`），
与正常时间显示的 `WINDOW_SCALE` 分开。窗口尺寸随该值线性变化（本机实测）：

| PLUGIN_SCALE | 插件窗口尺寸 |
|---|---|
| 1.00（Catime 默认） | 179×12 ← 极小 |
| 2.00 | 268×22 |
| 4.00 | 445×42 |
| 8.00 | 797×82 |

`PLUGIN_SCALE` 越大字越大、窗口越大；也可以在插件运行期间用鼠标直接缩放窗口，
Catime 会自动把新值写回 `config.ini`。

**位置方面有个 Catime 的限制**：正常时间与插件模式**共用同一对坐标**
（`CLOCK_WINDOW_POS_X/Y`），而两种模式的窗口尺寸不同——所以窗口变小后不会再贴着右下角。
本插件用「窗口贴角」解决：插件运行时会自己把窗口贴到指定角落（实测可移动外部窗口，
且 Catime 不会把它拉回），**退出插件后恢复正常时间的位置**：

```powershell
$PluginAnchor  = 'bottomright'   # 默认：贴工作区右下角（自动避开任务栏）
# 'keep' = 不动窗口；也可用 'bottomleft' / 'topright' / 'topleft' / 'center'
$AnchorMarginX = 0               # 离屏幕边缘的间距
$AnchorMarginY = 0
```

## 结束通知窗口（Catime 官方的那个）

它的**位置和尺寸都能改**（`config.ini [Notification]`）：

| 配置项 | 范围 | 说明 |
|---|---|---|
| `NOTIFICATION_WINDOW_WIDTH` | 350 ~ 1600 | 窗口宽度（**默认最小值就是 350**，偏小多半是因为它） |
| `NOTIFICATION_WINDOW_HEIGHT` | 48 ~ 900 | 窗口高度 |
| `NOTIFICATION_WINDOW_X` / `_Y` | — | 位置；**填 `-1` 表示自动**（贴工作区右下角、留 20px 边距） |
| `NOTIFICATION_FONT_SIZE` | 10 ~ 60 | 字号 = **窗口高度的这个百分比**（60 已是上限，所以想放大字要靠调高窗口高度） |

也可以直接在屏幕上拖动通知窗口来改位置，Catime 会写回配置。

## 阶段类型判定（哪一段算"工作"）

> **这一整节讲的是本插件自己的做法，不是 Catime 官方的规则。**
> Catime 官方没有"W/B 模板"这种写法，`config.ini` 和界面里都没有相关设置。
> 下面的 `'WB'` 只是本脚本内部使用的简写（Work / Break 首字母）。
> **日常使用不需要填任何东西**——保持默认为空即可；只有序列排法不常规时才需要它。

⚠️ **前提事实**：Catime 内部不记录"工作/休息"属性——源码里那个字段只会被赋值为
`IDLE` 或 `WORK`（枚举中的 `BREAK` / `LONG_BREAK` 从未使用），通知文本也只有"时长 + 轮次"。
所以"哪一段是工作阶段"完全取决于用户约定，插件只能推断。可用两种方式（脚本顶部 `$PhaseTypes`）：

| 方式 | 写法 | 适用 | 风险 |
|---|---|---|---|
| 自动（默认） | `$PhaseTypes = ''` | 序列**以工作段开始、工作与休息交替**（Catime 常见用法） | 以休息段开始、或连续两段工作时会判错 |
| 显式模板 | `$PhaseTypes = 'WBWB'` | **任意序列**：休息先开始 `'BW'`、连续工作 `'WWB'`、奇数长度 `'WBW'` 都能准确表达 | 改了序列却忘了同步改这行——长度不一致时插件会自动回退到自动模式，并在日志里说明 |

模板按 `POMODORO_TIME_OPTIONS` 的顺序**逐段**标注：`W` = 工作、`B` = 休息。

插件启动时会把最终采用的判定写进 `pomodoro_stats.log`，例如：

```
阶段类型: 2700,600,2700,1200 → WBWB（自动模式（第 1、3、5… 段 = 工作阶段））
阶段类型: 8,4 → BW（显式模板 BW）
阶段类型: 8,4 → WB（显式模板长度 3 与序列长度 2 不一致，已回退自动模式）
```

> 为什么不用"时长长的算工作"来自动推断？反例：经典 4 番茄结构
> `25 5 25 5 25 5 25 30` 里最长的是 30 分钟的**长休息**，会被误判为工作段
> （"超过中位数/最大值"这类规则都有类似的坑）。位置交替规则在这种序列上反而稳定，
> 因此自动模式采用位置规则，特殊序列交给显式模板。

## 安装

1. 把这两个文件一起复制到 Catime 插件目录：

   ```
   %LOCALAPPDATA%\Catime\resources\plugins\
   ```

   | 文件 | 作用 |
   |---|---|
   | **`pomodoro_stats.bat`** | **启动入口 —— 在 Catime 菜单里点这个** |
   | `pomodoro_stats_core.ps1` | 真正的统计逻辑（不要点它） |

   （也可以托盘右键 → `插件` → `打开插件文件夹` 打开该目录）

2. 托盘图标右键 → `插件` → 点击 **`pomodoro_stats.bat`** → 首次运行选 **「信任并运行」**。

3. 窗口即显示统计数字。脚本顶部的 `$LabelToday / $LabelWeek / $LabelTotal` 可改显示标签。

> **前置条件：Catime 的通知类型必须是 `CATIME`（默认值）。**
> 在 Catime 设置里：托盘右键 → `通知设置` → `通知方式` → 选 **「Catime通知窗口」**；
> 或直接编辑 `%LOCALAPPDATA%\Catime\config.ini` 中的 `NOTIFICATION_TYPE=CATIME`。
> 若为 `OS`（操作系统通知）或 `SYSTEM_MODAL`，插件无法可靠感知阶段完成事件，
> 会显示 `SET CATIME` 提示而不计数。原因见下文「为什么必须用 CATIME 通知类型」。

### 为什么输出里有 `<catime>` 标签（很重要）

Catime 在**开始任何计时动作时**（按倒计时、启动番茄钟）会做一次清理：

```c
void CleanupBeforeTimerAction(void) {
    ...
    if (!PluginData_HasCatimeTag()) {
        PluginManager_StopAllPlugins();   // 没有 <catime> 标签 → 停掉所有插件、关闭插件显示
    }
}
```

也就是说：输出里**不带 `<catime>` 标签的插件，会在你一开始计时时被直接杀掉**，
表现为"启动倒计时后插件显示消失、完成阶段也统计不到"。
因此本插件在输出末尾固定带上 `<catime></catime>`；Catime 会在该位置渲染当前计时/时间，
副作用是插件模式下也能看到倒计时，正好补上被插件文本挡住的计时显示。

### 为什么多一个 `.bat` 入口

Catime 启动 `.ps1` 插件时执行的是 `powershell.exe -NoProfile ... -File 脚本`，**靠 PATH
环境变量找 `powershell.exe`**。而 `powershell.exe` 位于
`%SystemRoot%\System32\WindowsPowerShell\v1.0\`，不在 `System32` 根目录——如果系统 PATH
里缺少这一项（有些机器/精简系统会缺），Catime 就会报 **`powershell.exe not found`**，
插件根本不会运行。

`cmd.exe` 位于 `System32`，一定找得到，所以用一个 `.bat` 入口、在里面对 PowerShell
使用**绝对路径**调用，即可绕开该问题、且不依赖任何系统设置改动。

## 依赖

- Windows 10/11 自带的 **PowerShell 5.1**（无需安装任何第三方组件、无需联网）
- Catime（在 v1.5.0 与最新版上均已核对插件与通知机制）

## 数据文件

- `pomodoro_stats.json`：与脚本同目录，保存累计数、每日明细与阶段索引。
  删除该文件即可把统计清零。
- `output.txt`：与脚本同目录，Catime 实时读取该文件用于显示。
- `pomodoro_stats.log`：与脚本同目录，记录启动参数、每次计数、以及循环中的异常
  （超过 64KB 自动重建）。正常使用下每天只增加几行。
- 明细超过 400 天的旧记录会被自动清理。

## 工作原理

1. Catime 每完成一个番茄钟阶段（工作或休息）都会弹一次通知。当通知类型为
   `CATIME` 时，该通知是一个窗口类名为 `CatimeNotificationClass` 的置顶弹窗。
2. 插件每 500 ms 用 `EnumWindows + GetClassName` 检测该窗口是否新出现
   （出现新窗口 = 一个阶段刚刚完成）。该机制经实测比 `FindWindowW` 按类名
   查找更可靠——`FindWindowW` 对非本进程注册的窗口类会返回 0。
3. 结合 `config.ini` 里 `[Pomodoro] POMODORO_TIME_OPTIONS` 的阶段序列，判断
   刚完成的是工作阶段还是休息阶段，**仅工作阶段计数**（即"完成一个阶段"计一个番茄，
   而不是完成整个循环才计）。
4. 为抵抗阶段索引漂移，插件优先用"距上次完成事件的间隔"匹配阶段时长来反推
   刚完成的是哪个阶段；匹配失败时回退到顺序索引；间隔远超任何阶段时长时
   视为开始了新一轮番茄钟。

### 资源占用

常驻一个 PowerShell 进程（Windows 自带），每 500 ms 一次系统调用级的窗口枚举，
无网络访问、无第三方依赖；仅在阶段完成时写一次状态文件，Catime 侧读取
`output.txt` 本身是事件驱动的。

## 为什么必须用 CATIME 通知类型

- Catime 的 `complete_pomodoro_cycles` 只是进程内的内存变量，既不写
  `config.ini` 也不写日志，插件（只通过文件通信）无法直接读取。
- 通知类型为 `CATIME` 时，阶段完成会产生可稳定检测的专属窗口类
  （`CatimeNotificationClass`，v1.5.0 与最新版一致）。
- 通知类型为 `OS` 时，Catime 走的是 `Shell_NotifyIcon` 系统气球，由 Explorer
  渲染，实测**不稳定**：系统会对短时间内重复的气球做节流抑制，且窗口类不专属
  于 Catime，无法作为可靠信号。

## 已知限制

- 使用**普通倒计时**（非番茄钟模式）时，倒计时结束也会弹出同款通知，会被计为
  一次工作阶段完成。建议只在番茄钟模式下使用本插件。
- 番茄钟中途停止再重新开始，阶段索引可能短暂错位，通常会在下一次完成时自纠正。
- Catime 关闭通知（`NOTIFICATION_DISABLED=TRUE`）或通知类型非 `CATIME` 时无法计数。

## 手动验证（约 1 分钟）

1. 确认通知类型为 `CATIME`（见上文前置条件）。
2. 托盘图标**右键** → **`插件`** → 点击 **`pomodoro_stats.bat`** → 弹窗里选 **「信任并运行」**
   （菜单里还会有一个 `pomodoro_stats_core.ps1`，那是逻辑文件，**不要点它**）。
   窗口应显示 `T0 W0 A0`（或已有数据）。
3. 快速触发一次"阶段完成"：**左键**单击托盘图标 → 在「倒计时」输入框输入 **`10s`** 回车
   （倒计时结束弹出的通知与番茄钟阶段完成时完全相同，会被计为 1 个工作阶段）。
   也可以走真实番茄钟，但默认阶段是 45 分钟，太久。
4. 窗口数字应从 `T0 W0 A0` 变为 `T1 W1 A1`（休息阶段完成时数字不变）。

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 窗口显示 `powershell.exe not found` | 误点了 `pomodoro_stats_core.ps1`。点 `pomodoro_stats.bat` 那个入口 |
| 一开始倒计时插件就没了、显示变空白 | 旧版本问题，已修复（输出末尾带 `<catime>` 标签）；重新点一次 `pomodoro_stats.bat` 即可 |
| 窗口显示 `SET CATIME` | 通知类型不是 `CATIME`（见上文前置条件）；改完保存即生效 |
| 通知弹出了但数字不动 | 插件没在运行：托盘右键 → `插件`，确认 `pomodoro_stats.bat` 前有 ✓ |
| 菜单里列出两个 `pomodoro_stats*` | 正常，`.bat` 是入口，`..._core.ps1` 是逻辑文件 |
| 想清零统计 | 删除插件目录下的 `pomodoro_stats.json` |
| 想查原因 | 看同目录的 `pomodoro_stats.log`（启动参数、计数、异常） |
